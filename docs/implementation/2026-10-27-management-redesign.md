# Management and mobile navigation redesign

This supersedes the earlier workspace navigation notes. The deployed implementation is a verification release, not acceptance of the full original overhaul specification.

Kite uses its own single header, in normal layout flow. The extra shell header and Home/Kite/Echo/Space navigation strips are removed. The Sterling icon opens a native modal workspace selector above trading panels and media frames. The icon remains visible and touchable in the mobile app layout. Settings actions open that same selector. Mobile Tools and app pages are deduplicated by destination identity.

Administrators land directly in Administration, irrespective of feature grants. Management has user/account summaries, a request inbox, user permissions, broker connections and Telegram destinations. A single searchable combobox replaces separate search and account dropdown controls, including manual broker creation, reassignment and integration owner selection. The existing orange/light admin design language is retained. Settings delegation uses understandable action checkboxes for the user's own resources; existing exact resource scopes remain inspectable/removable.

An ordinary user selecting a restricted workspace automatically creates one durable access request. Repeated visits reuse the pending request rather than duplicating it. The user sees that the request was sent, or that it was declined. Admin login shows the pending count and review banner. Approval updates only the requested feature, increments policy revision, and writes audit/outbox records in the same transaction. Rejection leaves permissions unchanged. Review is restricted to the designated administrator and conflicting/repeated decisions are refused. No emails or external messages are sent.

Existing Kite profiles can be reassigned to one active Sterling user at a time. The adapter locks both tenants in a fixed order, verifies flat broker and local exposure, refuses pending activity, and performs ownership CAS plus redacted lineage audit atomically. Old broker access/refresh sessions are cleared and the target reconnects; old journals are not rewritten. No live broker assignment was changed during development or automated acceptance. Adding a profile manually still requires explicit assignment and a separate Kite grant. This remains an adapter over the assigned-account provider store, not the full independent/unassigned registry.

Validation: 58 targeted backend tests, 84 frontend tests, TypeScript and eight browser flows passed. Browser coverage includes real terminal shell/menu/CSS touch handling with synthetic trading panes, access request → admin approval → user access, fresh settings, manual broker creation/reassignment, integration owner search, and desktop/mobile isolation. Backend tests cover rejection, deduplication, permissions, audit rollback, ownership CAS, session clearing and exposure refusal. Live deployment verification and snapshot receipts are stored under `.runtime/deployments/20261027-management-redesign/`.
